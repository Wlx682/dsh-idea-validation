## 目标

把一次性 `Collect → Discover → Challenge` 文档生成器改造成跨轮次、可恢复、有人类门禁的想法决策工作流。流程从原始想法推进到问题确认、定向取证、方案比较、最小实验和实施交接；未经人类批准不得自动跨门禁。

## 本轮 Scope

- S1：有状态的想法捕获、澄清和问题确认。
- S2：单一高风险假设、定向取证和证据决策。
- S3：方案比较、可归因最小实验、关键路径和实施交接。
- S4：阶段级修复、幂等/乐观锁、专项回归、preset 与文档同步。
- S5：所有非终态门禁使用可选择卡片；点击或自定义回答后沿同一 case 自动继续。
- S6：澄清阶段按待确认事项拆卡；三个问题生成三张各自带语义选项的卡片。

## 非目标

- 不在“问题发现模式”中直接修改业务代码或自动创建 Goal。
- 不把外部行业材料当成用户组织内部事实。
- 不替人类做 proceed / pivot / defer / reject 决策。

## 验收

1. 每次工具调用最多推进一个阶段，返回 `caseId`、`revision`、状态快照和唯一门禁。
2. 用户澄清进入后续状态，不再只传原始请求。
3. 未显式授权的工作区路径不能成为工作区证据。
4. 结构失败只重试当前阶段一次，不重跑已完成阶段。
5. 实验必须包含干预、比较方式、一个主指标、护栏和通过/失败阈值。
6. 实施交接必须包含最小 Scope、AC、埋点、回滚与下一动作。
7. 专项回归和完整测试均通过。
8. 非终态结果由根 Agent 调用 `ask_user_question` 呈现为卡片，子 Agent 不得提问；点击答案必须映射到同一 `caseId` 和 `expectedRevision`，不得重启 case。
9. 澄清问题不得把多个事项或 A/B/C 伪选项塞进正文；每个事项独占一张卡，并携带回答该问题的选项，整组回答后才继续一次。
